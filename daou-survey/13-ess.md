## ESS 골격

다우 ESS는 별도 서브앱(확장 GNB 200px + 콘텐츠 패널)이지만, 콘텐츠 문법은 gw와 같다
(흰 시트 + 섹션 + 표). 우리는 기존 셸(레일/패널/흰 시트)에 그대로 얹는다.

## 인사 (#hr/my-hr-info)

- 패널 항목: **내 인사정보** / **증명서 발급 신청**
- **인사카드**: 사진 자리 + 라벨-값 필드 그리드 — 필드 행 **270×28**, 라벨 **14/500 rgb(51,51,51)**, 값 14/400
  - 필드: 이름 · ID · 직원구분 · 부서/직책 · 직위/직급 · 입사일 · 사원번호 · 직통번호 · 휴대전화
- **탭 스트립 14칸**: 기본 / 신상 / 인사발령 / 경력 / 포상·징계 / 인사평가 / 교육 / 자격 / 어학 / 해외출장 / 학력 / 가족 / 프로젝트 / 계약
  - 탭 **h-40 · 14px**, **활성 = border-bottom 2px 검정** (필 세그먼트가 아니라 밑줄 탭)
- 기본 탭 구성: "직원정보"(주민번호·국적·체류자격·영문이름·성별·생년월일·주소) +
  "직원이력"(채용구분·조직·최종발령일·재직기간·경력기간·직종·직군·직무) + "퇴사정보"
- **증명서 발급 신청** (#hr/cert-isu): 조회 필터 + 결과 표 + 버튼(조회 · **증명서 발급 요청** · 삭제 · 전자결재)

## 급여 (#payroll/my-pay)

- 상단: 인사카드 요약(같은 필드 그리드)
- **"급여상세"** 섹션: 급여유형 · 연봉 · 월급 · 고정수당 · 고정수당 포함여부 + "자세히 보기"
- **"급(상)여명세서"** 섹션: 기간 조회 + **인쇄** 버튼 + 표
  - 컬럼: 급(상)여월 · 급(상)여지급일 · **지급합계 · 공제합계 · 공제 후 지급액** + 하단 합계 행
  - 상세: 사원명 · 부서 · 지급항목 합계 · 공제항목 합계 · 공제 후 지급액 (+ 항목별 명세)

## 계약 (#econtract)

- 테넌트 미설정으로 빈 화면 — 실측 불가. 목록 문법은 급여명세 표 축으로 구성:
  계약서명 · 상태(작성중/서명완료/만료) · 체결일 · 파일. 모두싸인 연동 자리(스펙 07).

## 우리 구현 결정

- **모듈 3개 신설**: /hr(인사) · /payroll(급여) · /contracts(계약) — 레일 순서는 다우처럼 뒤쪽.
- **데이터 모델 (마이그레이션 30)**:
  - `payroll_profiles`(급여상세: 급여유형·연봉·월급·고정수당) · `payroll_slips`(월별 명세:
    급여월·지급일·합계 3종) · `payroll_slip_items`(지급/공제 항목별) — **RLS 본인+system_admin만.
    급여는 이 프로젝트에서 가장 민감한 데이터다 — 동료 급여 불가시가 e2e 필수 케이스.**
  - `certificate_requests`(증명서: 종류 재직/경력·용도·상태 신청/발급/반려) — PDF 양식은 대기(스펙 08),
    신청→관리자 처리 흐름은 동작.
  - `employment_contracts`(계약: 제목·상태·체결일·파일) — 모두싸인 대기, 목록·열람 동작.
- 인사카드는 employees 기존 데이터로 채우고, 다우 탭 14종 중 **우리 데이터가 있는 것만**
  (기본·인사발령↔조직변경이력·경력↔프로젝트·계약) 탭으로 세운다 — 없는 탭을 빈 껍데기로 세우지 않는다.
- 관리자 입력: /admin/payroll(명세 등록·항목), /admin/hr(증명서 처리), /admin/contracts(계약 등록).
